# Agent Note: 会话删除

Status: implemented

[English](2026-08-21-session-deletion.md) | 中文

## 问题

知我侧边栏会列出持久会话，但没有用于清理不再需要的历史记录的破坏性操作。只在浏览器中移除行会使它在刷新后重新出现；绕过生命周期所有者直接删除实时日志，则可能与待处理写入发生竞态，产生错误的移除帧或破坏持久化。Workspace 移除与归档属于不同操作，它们都会保留会话日志。

## 决策

`session.delete({ sessionId })` 永久删除恰好一份普通会话日志。Host 会等待同 id 的并发创建，拒绝 subagent 所有的会话以及由其他组件拥有的实时会话，并保留自己创建或从冷态恢复的每个生命周期的 `AgentHandle`。实时目标会通过该 handle 释放，使活动轮次、事件排空与会话退役都经过其所有生命周期完成。

在释放过程中，Host 会抑制普通 `session/disposed` 移除增量。随后调用 `SessionPersistence.delete`：其协调器等待退役完成，让该操作与同 id 的写入串行执行，拒绝仍然存在的实时所有者，并在后端删除 JSONL 工件或 SQLite 行之前让保留的 preparation 状态失效。只有持久删除成功后，Host 才会从每个 Workspace 账本与全局归档集合中移除该 id，并发送一次 `host/session-removed` 帧。持久删除失败时，RPC 返回错误，但不发送移除帧，也不变更 Workspace，因此可见行会保留以供重试。

`SessionManager.delete` 让成功的一元响应与 Host 增量经过同一条幂等本地移除路径。删除当前 id 时，`SessionRuntime.delete` 会选择最新的剩余会话。知我会话行提供垃圾桶图标，并打开破坏性确认 `Modal`；请求待处理期间禁止关闭和重复提交，失败时对话框保持打开并显示可重试错误。

该操作不会删除会话 cwd、附件存储对象、普通 fork 后代或 subagent 后代日志。这些对象具有不同的所有权与保留规则。通用 Workspace 浏览器继续提供非破坏性的 Archive 操作；破坏性删除是知我会话行上明确命名的操作。

## 考虑过的替代方案

**只删除客户端行。** 不予采纳，因为持久日志会在下一次 `session.list` 基线中重新出现。

**在会话实时运行时删除持久化。** 不予采纳，因为待处理事件写入与生命周期清理会和破坏性后端操作发生竞态。

**在 `session/disposed` 时发布移除。** 不予采纳，因为之后若持久化失败，所有已连接客户端都会误以为仍然存储的会话已经删除。

**级联删除后代、附件或工作目录。** 不予采纳，因为选中的会话并不拥有这些独立记录或用户文件。

## 后果

删除所选会话日志后无法撤销。持久删除失败时，行与 Workspace 账本保持可见，可供重试；成功删除会通过一元响应和 Host 流收敛，并在刷新后保持缺失。不可逆的持久化提交完成后，Workspace 清理由系统尽力执行；若其存储写入失败则记录警告，会话列表持久化仍是权威可见性基线。
